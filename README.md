Практикалық жұмыс №4 бойынша есеп

Тақырыбы: Пайдаланушы интерфейсінің макеттерін әзірлеу және локалды деректер қорын (SQLite) кірістіру.
Жоба: F1 Tracker (Flutter)
Репозиторий: github.com/mukhtarqqa/f1
 (тармақ: main)

1. Орындалған жұмыстардың мазмұны

Бұл жұмыста қолданба толығымен Offline-First архитектурасына көшірілді. Барлық ақпарат интернетсіз құрылғы жадындағы реляциялық SQLite деректер қорында сақталады.

Барлық 20 тапсырма толық көлемде орындалды:

Тапсырмалар бойынша нақты нәтиже:

Негізгі ақпарат түрлері анықталды (1-тапсырма):

Автодромдар мен трассалар (Circuits)
Конструкторлар мен командалар (Teams)
Жүргізушілер / пилоттар (Drivers)
Гран-при күнтізбесі мен жарыстар (Races)
Пайдаланушы еске салғыштары (Reminders)
Таңдаулы жарыстар тізімі (Favorites)

6 өзара байланысты Entity / Model құрылды (2–3 тапсырмалар):

F1Circuit — трасса идентификаторы, атауы, елі, қаласы, ұзындығы (lengthKm), бұрылыстар саны (turnsCount).
F1Team — команда атауы, базасы, қозғалтқыш өндірушісі, ұпайлары, чемпиондық титулдары, түсі (colorHex).
F1Driver — жүргізуші аты, 3 таңбалы коды (code), нөмірі, командасының кілті (teamId), ұпайлары, подиумдары.
F1Race — раунд нөмірі, трасса кілті (circuitId), атауы, елі, күні, айналым саны (laps), аяқталу белгісі (isCompleted), жеңімпазы (winnerDriverId).
F1Reminder — еске салғыш идентификаторы, жарыс кілті (raceId), атауы, хабарлау уақыты (advanceMinutes), ескертпелер (notes).
F1Favorite — таңдаулы объект түрі (targetType), объект идентификаторы (targetId), қосылған уақыты.
Барлық модельдерге toMap(), fromMap(), copyWith() әдістері енгізілді.

Модельдер арасындағы реляциялық байланыстар (4-тапсырма):

drivers.team_id 
→
→ teams.id (Сыртқы кілт / Foreign Key, ON DELETE CASCADE);
races.circuit_id 
→
→ circuits.id (Сыртқы кілт);
races.winner_driver_id 
→
→ drivers.id (Жеңімпаз байланысы);
reminders.race_id 
→
→ races.id (Сыртқы кілт, ON DELETE CASCADE);
favorites.target_id 
→
→ races.id.

Локалды деректер қорын таңдау және баптау (5–7 тапсырмалар):

Таңдалды: SQLite (sqflite + кросс-платформалық sqflite_common_ffi).
AppDatabase синглтоны құрылды.
PRAGMA foreign_keys = ON; арқылы тұтастық шектеулері іске қосылды.
Қосымша алғаш рет іске қосылған кезде база автоматты түрде бастапқы ресми деректермен (Seed data) толтырылады.

CRUD операциялары (8–11 тапсырмалар):

Create (Құру):
Жаңа жарыс қосу диалогы (Күнтізбе экранындағы + түймесі).
Жаңа еске салғыш құру экраны (ReminderEditorScreen).
Read (Оқу):
Басты беттегі статистика, күнтізбе тізімі, турнирлік кесте және таңдаулылар экраны деректерді SQLite-тан тікелей оқиды.
Update (Өзгерту):
Жарыс мәртебесін ауыстыру («Аяқталды деп белгілеу / Update» түймесі).
Бар еске салғыштың уақытын, атауын және ескертпесін өңдеу.
Delete (Өшіру):
Еске салғыштарды тізімнен жою (Popup меню арқылы).
Жарыстарды таңдаулылардан өшіру (жүрекше түймесі арқылы).

Repository / Service архитектуралық қабаты (12-тапсырма):

F1Repository — деректер қорымен тікелей жұмыс істейтін тәуелсіз репозиторий.
AppStore — UI мен Repository арасындағы реактивті байланысты қамтамасыз ететін жаһандық күй басқарушысы (ChangeNotifier).

Деректерді іздеу (Search) (13-тапсырма):

Жарыс атауы, елі, трассасы және жүргізушілер мен командалар бойынша іздеу жасалды (SearchScreen және CalendarScreen).
Қазақша/кириллица және латын әріптерін толыққанды сәйкестендіретін Unicode-қауіпсіз іздеу жүзеге асырылды.

Деректерді сүзгілеу (Filtering) (14-тапсырма):

Күнтізбе экранында үш позициялы фильтр:
Барлығы (барлық кезеңдер);
Алдағы (is_completed = 0);
Аяқталған (is_completed = 1).

Кемінде екі параметр бойынша сұрыптау (Sorting) (15-тапсырма):

Жарыстар бойынша:
Кезең нөмірінің өсуімен (round ASC, name ASC);
Кезең нөмірінің кемуімен (round DESC, name ASC);
Атауы бойынша А 
→
→ Я (name ASC, round ASC);
Атауы бойынша Я 
→
→ А (name DESC, round ASC).
Жүргізушілер бойынша:
Ұпайлар санының кемуімен (points DESC, podiums DESC);
Ұпайлар санының өсуімен (points ASC, name ASC);
Аты-жөні бойынша (name ASC);
Подиумдар саны бойынша (podiums DESC).

Favorites (Таңдаулылар) жүйесі (16-тапсырма):

Таңдаулы жарыстар favorites кестесіне түседі және қосымша жабылғаннан кейін де сақталып қалады.

Empty State — деректер болмағанда хабарлама көрсету (17-тапсырма):

Іздеуден ештеңе табылмағанда, сүзгі бойынша жарыс болмағанда немесе таңдаулылар бос болған кезде пайдаланушыға түсінікті иконкасы мен сүзгіні тазалау әрекеті бар EmptyState виджеті көрсетіледі.

Қателерді өңдеу (Error Handling) (18-тапсырма):

Арнайы F1DatabaseException қателіктер класы құрылды.
Барлық күтпеген жағдайлар try/catch арқылы ұсталып, пайдаланушыға экранда ескерту баннері немесе SnackBar арқылы көрсетіледі.

Офлайн жұмыс және сақталуды тексеру (19–20 тапсырмалар):

Қосымша интернетсіз автономды жұмыс істейді.
Автоматтандырылған сынақтар арқылы (тест №20) жаңа жазба енгізіліп, деректер қоры мен қосымша қайта бапталғаннан кейін де сол жазбаның базада сақталатыны тексерілд
