# F1 Tracker

## Данные сезона 2026

В Supabase загружен официальный срез на **5 ноября 2026**: 24 пилота в личном
зачёте (включая участвовавших резервных пилотов), 11 команд, 23 гонки, 19 завершённых
Гран-при и 418 строк финишных протоколов. Очки чемпионата включают спринты;
подиумы пилотов считаются по основным гонкам текущего сезона. Командные очки
импортируются отдельно от суммы очков пилотов, с учётом официальных санкций.

Источники: [личный зачёт](https://www.formula1.com/en/results/2026/drivers),
[командный зачёт](https://www.formula1.com/en/results/2026/team),
[календарь](https://www.formula1.com/en/racing/2026) и
[протоколы гонок](https://www.formula1.com/en/results/2026/races).

Срез хранится в `supabase/data/season_2026.json`, готовое обновление базы —
`supabase/migrations/004_current_2026_season.sql`. SQL использует одну транзакцию
и upsert: повторное выполнение не создаёт дубликатов, существующие ID, избранное
и напоминания сохраняются. Для нового проекта сначала выполните миграцию `001`.
Для новых трасс `turns_count = 0` означает отсутствие числа поворотов в источнике.

Экран результатов читает таблицу `race_results`: позиции, время, число кругов и
очки конкретной гонки. Для предстоящих гонок отображается отсутствие результатов.
При равных очках пилоты в чемпионате следуют официальному `championship_position`.
После обновления базы перезапустите приложение или обновите страницу Chrome.

Повторное создание SQL из сохранённого среза, без доступа к сети и базе:

```powershell
python tools/prepare_f1_2026.py --from-snapshot
```

Для нового среза 2026 года установите `requests` и `beautifulsoup4`, затем выполните
`python tools/prepare_f1_2026.py --as-of YYYY-MM-DD` с фактической датой получения.
Скрипт проверяет связи и данные, создаёт файлы для проверки, но сам в Supabase не пишет.
Это разовое обновление; автоматическая синхронизация с Formula1.com не настроена.

## Запуск в Chrome (без Android SDK)

Из корня проекта запустите `./run_chrome.ps1`. Скрипт использует Supabase из локальной
конфигурации `.vscode/launch.json` либо переменных `SUPABASE_URL` и `SUPABASE_ANON_KEY`.
Можно передать `-SupabaseUrl https://YOUR_PROJECT.supabase.co -SupabaseKey YOUR_PUBLIC_KEY`.
Адрес разработки — `http://localhost:5173`; постоянный порт позволяет Chrome сохранять
сессию и разрешение камеры для одного origin. В VS Code также доступна конфигурация
`F1 Tracker (Chrome, Supabase)`. Android SDK и сборка APK для этого запуска не нужны.

### Realtime календарь

После миграций `001` и `002` выполните
[`003_races_realtime.sql`](supabase/migrations/003_races_realtime.sql) в SQL Editor своего
Supabase-проекта. Новые библиотеки не требуются: `supabase_flutter` уже содержит
WebSocket-клиент Realtime. Реализация следует
[официальному API Supabase Flutter](https://supabase.com/docs/reference/dart/subscribe).

Авторизованный клиент подписывается на INSERT/UPDATE/DELETE таблицы `races`.
Администратор отправляет изменения через существующие формы и кнопку изменения статуса
гонки; запись через PostgREST запускает серверное событие, которое остальные клиенты
получают по WebSocket. Календарь обновляется с сохранением поиска, фильтра и сортировки.
Это обновления данных приложения, а не подключение к внешнему источнику live-результатов F1.

В календаре показан статус Live. SDK автоматически повторяет соединение после разрыва;
после каждой успешной подписки приложение повторно получает данные, включая изменения,
пропущенные без сети. При ошибке остаются последние загруженные гонки; доступна кнопка
повторного подключения. Выход из аккаунта и закрытие хранилища отменяют подписку.
RLS сохраняет право изменения общего календаря только за администратором.

Проверка в двух сессиях Chrome (обычное окно и инкогнито):

1. Войдите в оба аккаунта и откройте календарь; дождитесь статуса Live.
2. В аккаунте администратора измените гонку или отметьте её завершённой. Во втором
   окне изменения должны появиться автоматически, без обновления страницы.
3. Отключите сеть в DevTools второго окна, измените гонку в первом и восстановите
   сеть. Второе окно должно получить актуальные данные после переподключения.
4. Разрешите камеру и отсканируйте QR `F1RACE:usa`; откроется соответствующая гонка.
   Отдельно проверьте запрет камеры и повторный запрос разрешения.
5. Проверьте регистрацию, неверный пароль, восстановление сессии после перезагрузки
   на том же адресе и выход из профиля.

Автоматические проверки: `flutter analyze` и `flutter test`. Веб-сборка:
`flutter build web --dart-define=SUPABASE_URL=... --dart-define=SUPABASE_ANON_KEY=...`.
Результат находится в `build/web`.

F1 Tracker — жарыстар күнтізбесін, жүргізушілерді, командаларды, таңдаулыларды және еске салғыштарды көруге арналған Flutter қолданбасы. Деректер PostgreSQL базасында сақталады және Supabase PostgREST арқылы қауіпсіз алынады. Flutter клиенті PostgreSQL базасына тікелей қосылмайды.

## PostgreSQL-ді баптау

1. Supabase жобасын жасаңыз.
2. Supabase SQL Editor ішінде [`supabase/migrations/001_initial_schema.sql`](supabase/migrations/001_initial_schema.sql) файлын орындаңыз. Ол кестелерді, жол деңгейіндегі қауіпсіздік саясаттарын және мысал деректерін жасайды.
3. Supabase Authentication ішінде Email provider-ін қосыңыз. Email растауын қосуды немесе өшіруді жоба талаптарына сай таңдаңыз.
4. Жоба баптауларынан жоба URL-ін және жалпыға қолжетімді anon/publishable кілтін көшіріңіз. Қолданбаға `service_role` кілтін немесе дерекқор құпиясөзін ешқашан енгізбеңіз.
5. Қолданбаны URL мен жалпыға қолжетімді кілтті Dart define ретінде беріп іске қосыңыз:

```powershell
flutter run -d chrome --dart-define=SUPABASE_URL=https://YOUR_PROJECT_ID.supabase.co --dart-define=SUPABASE_ANON_KEY=YOUR_PUBLIC_ANON_KEY
```

Бұл нұсқа Flutter Web үшін дайындалған. URL мен кілт клиент жағында қолдануға арналған; жеке деректерді жол деңгейіндегі қауіпсіздік саясаты қорғайды.

## Практикалық жұмыс №6 — тіркелу, күй және QR-сканер

- Тіркелу және кіру үшін email/password аутентификациясы қолданылады. Тіркелу формасы аты-жөнді, жарамды email мен кемінде 6 таңбалы құпиясөзді тексереді; сервер қайтарған қате формада көрсетіледі.
- Профиль Supabase Auth ішіндегі пайдаланушы аты мен email-ін көрсетеді. Шығу Supabase сессиясын жояды. Supabase SDK сессияны құрылғыда сақтап, келесі іске қосқанда автоматты түрде қалпына келтіреді.
- Қолданба күйі `ChangeNotifier` және Provider арқылы басқарылады.
- Басты беттегі **F1 QR-сканері** `F1RACE:<race-id>` пішіміндегі кодты оқып, тиісті жарыс мәліметін ашады. Браузер камера рұқсатын сұрайды; рұқсаттан бас тартқанда қайта сұрау, ал бұғатталғанда сайт баптауларынан рұқсат беру жолы түсіндіріледі. Камераға қол жеткізу үшін HTTPS немесе localhost қажет.

Тексеру: жаңа пайдаланушыны тіркеп, жүйеден шығып қайта кіріңіз; қате құпиясөзді тексеріңіз; браузерді қайта ашқанда сақталған сессияның қалпына келетінін тексеріңіз. QR-сканерге рұқсат беріп, `F1RACE:usa` мазмұны бар кодты сканерлеңіз. Рұқсаттан бас тарту және браузер баптауларынан камераны бұғаттау жағдайларын бөлек тексеріңіз. `/app`, `/race` немесе `/scanner` маршруттарын жүйеге кірмей ашқанда қолданба кіру экранына қайтарады.

## Практикалық жұмыс №5 — REST API және интерактивті прототип

Осы практикалық жұмыстың әр тармағына қандай дәлел скриншот түсіру керегін [`PRACTICE5_SCREENSHOT_GUIDE.md`](PRACTICE5_SCREENSHOT_GUIDE.md) нұсқаулығынан қараңыз.

Жарыстар күнтізбесі Supabase PostgREST API интерфейсін қолданады. API негізгі мекенжайы:
`https://<project-id>.supabase.co/rest/v1`. Flutter Supabase SDK әр сұрауға жалпыға қолжетімді API кілтін және ағымдағы пайдаланушының қолжетімділік токенін қосады.

| Endpoint | HTTP әдісі | Қолданбадағы операция |
|---|---|---|
| `/races?select=*&order=round.asc` | GET | Жарыстарды алу, іздеу, сүзу және сұрыптау |
| `/races` | POST (upsert) | Күнтізбе формасынан жаңа жарыс қосу |
| `/races?id=eq.<id>` | PATCH | Жарысты өңдеу немесе аяқталды деп белгілеу |
| `/races?id=eq.<id>` | DELETE | Растағаннан кейін жарысты өшіру |
| `/circuits?select=*&order=name.asc` | GET | Трассалар туралы анықтамалық деректерді алу |
| `/drivers?select=*&order=points.desc` | GET | Жүргізушілер рейтингін алу |
| `/teams?select=*&order=points.desc` | GET | Командалар рейтингін алу |
| `/reminders` | GET / POST / DELETE | Ағымдағы пайдаланушының еске салғыштарын оқу және басқару |
| `/favorites` | GET / POST / DELETE | Ағымдағы пайдаланушының таңдаулыларын оқу және басқару |

JSON форматындағы жарыс жазбалары `F1Race` Dart моделіне түрлендіріледі және кері түрлендіріледі. `AppStore` соңғы алынған нәтижелерді жадта сақтап, серверге дерек сәтті жазылғаннан кейін күнтізбені жаңартады. Жарыстарға арналған сұраулардың күту уақыты — 15 секунд. Күнтізбе жүктелу барысын, сервер/желі қателерін және қайта сұрау батырмасын көрсетеді. Қосу, өңдеу немесе өшіру сәтті болғаны сервер операциясы аяқталғаннан кейін ғана хабарланады. Жарыс күнтізбесіндегі деректерді өзгерту үшін Supabase жүйесінде сенімді `app_metadata.role = admin` рөлі бар пайдаланушы қажет. Бұл талап миграциядағы жол деңгейіндегі қауіпсіздік саясатымен қамтамасыз етіледі.

CRUD операцияларын тексеру үшін Supabase параметрлері орнатылған және `admin` тест пайдаланушысы бар кезде қолданбаны іске қосып, күнтізбедегі қосу, өңдеу және өшіру әрекеттерін пайдаланыңыз. Supabase жүйесіндегі `races` кестесінің өзгергенін тексеріп, күнтізбенің жаңартылғанына көз жеткізіңіз. Қате сценарийлерін тексеру үшін желіні өшіріңіз немесе `admin` рөлін алып тастаңыз: қолданба бұрын жүктелген деректерді сақтап, сұрау қатесін көрсетуі тиіс. Сервер ұзақ жауап берсе немесе қолжетімсіз болса, 15 секундтан кейін timeout қатесі көрсетіледі.

## Ескертпелер

- `001` миграциясындағы деректер — мысалдар. `004` миграциясы оларды 2026 жылғы 5 қарашадағы ресми чемпионат деректерімен жаңартады; Formula1.com-нан автоматты синхрондау жоқ.
- Таңдаулылар мен еске салғыштар жүйеге кірген Supabase пайдаланушысына тиесілі.
- Email арқылы кіру Supabase Auth-пен орындалады. Ортақ жарыстарды қосу, өзгерту және өшіру үшін сенімді `app_metadata.role = admin` рөлі қажет; әкімші емес пайдаланушыларға бұл әрекеттердің батырмалары көрсетілмейді, ал RLS оларды сервер жағында да қорғайды. Әкімші рөлін Flutter клиентінен тағайындамаңыз; оны сенімді әкімшілік жолмен беріңіз. Бұрыннан бар Supabase жобасында ескі кең саясаттар қалса, `supabase/migrations/002_lock_down_race_writes.sql` миграциясын SQL Editor-де орындаңыз.
